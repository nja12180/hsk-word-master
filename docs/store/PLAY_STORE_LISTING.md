> **핵심 규칙**: Play는 업로드된 512×512 이미지의 **모서리를 자동으로 둥글게 깎습니다.**

**이번에 발견·수정한 결함**

최초 아이콘은 "검정 배경 위에 둥근 사각형을 얹은" 형태로 내보내져 있었습니다.

**수정 방식 — 코랄 가중 push-pull 인페인팅**

1. 네 모서리에서 `휘도 < 40`인 픽셀을 **4-연결 BFS 플러드필**로 확장 → 라운딩 영역만 정확히 추출(10,755 px)
2. 마스크를 8 px 팽창시켜 경계 여유 확보
3. **코랄(배경)로 분류된 픽셀에만 가중치 부여** — 팬더의 검은 털이 평균에 섞이지 않도록 차단
   (이 차단이 없으면 모서리가 약 5 휘도만큼 어두워지고 호형 이음매가 남습니다)
4. 8단계 push-pull 피라미드로 촘촘한 곳에서 성긴 곳으로 색을 전파
5. 경계는 blur 2 px의 좁은 페더로만 혼합 → 안쪽 라운딩 테두리를 그대로 보존

### 2.6 AI 애셋 선언 (AI asset declaration)

Play Console은 스토어 등록정보의 **시각 자산별로** "AI를 사용하여 생성 또는 수정한
애셋"인지 개별 선언하도록 요구합니다. Google 공식 문서 기준:

> "**애셋별 신고:** 동영상 또는 이미지와 같은 개별 항목은 각각 자체적인 기준에 따라
> 개별적으로 선언되어야 합니다."
> — support.google.com/googleplay/android-developer/answer/17262077

> "선언된 애셋은 Google Play 스토어 및 애셋이 사용되는 다른 표시 경로에서
> **AI 라벨이 지정됩니다.**"

#### 2.6.1 결론 — **「AI를 사용하여 생성 또는 수정한 것으로 애셋 라벨 지정」** 선택

단, **개별 애셋 단위로 나누어** 체크합니다. 전체 일괄 체크가 아닙니다.

| 애셋 | AI 생성 여부 | 라벨 | 근거 |
|---|---|---|---|
| **앱 아이콘** `play_icon_512.png` | **예** | ✅ **체크** | 팬더 마스코트가 생성형 이미지 AI 산출물. 원본 `icon_1024_master.png`는 검정 배경에 아이콘을 얹은 형태로, 생성 모델의 전형적 출력 패턴이며 선택·보정 외에 재작화하지 않았습니다 |
| **피처 그래픽** `feature_graphic_1024x500.png` | **예** | ✅ **체크** | 배경 그라데이션·타이포는 직접 제작했으나, **우측에 위 아이콘(팬더)을 그대로 합성**했으므로 AI 생성 요소를 포함합니다 |
| 스크린샷 `phone_01~07` (7장) | **아니요** | ⬜ **해제** | 전부 **실제 앱을 실행해 캡처한 UI**. 합성 인물·AI 배경·가짜 목업 없음 (§2.6.3 실측) |
| 홍보 동영상 | 해당 없음 | — | 제출하지 않음 |

> **왜 아이콘을 「예」로 해야 하나?** 생성형 AI로 만든 이미지를 쓰고도 「아니요」로
> 선언하면, Play의 자동 분류기가 합성 이미지를 탐지할 경우 **심사 보류·거부** 사유가
> 됩니다. 반대로 정직하게 선언했을 때 ASO에 불이익이 있다는 근거는 없습니다.
> 라벨은 **앱이 AI로 동작한다는 뜻이 아니라, 스토어 이미지가 AI로 만들어졌다는
> 투명성 표시**입니다.

#### 2.6.2 라벨이 붙으면 생기는 일

| 항목 | 내용 |
|---|---|

| ASO 영향 | 없음 (라벨은 검색 순위·노출에 불이익을 주지 않음) |

| 점검 항목 | 결과 |
|---|---|
| LLM·이미지 생성 API 호출 | **0건** (`openai`·`gemini`·`claude`·`http://`·`https://` 전부 미검출) |
| 네트워크 권한 | **없음** (APK 실측, §3.8.1) |
| 생성형 AI 의존성 | **없음** — `provider`, `hive`, `shared_preferences`, `flutter_tts`, `cupertino_icons` 뿐 |
| TTS 발음 | **기기 내장 엔진** (`flutter_tts` → OS TTS: `setLanguage('zh-CN')`). 생성형 모델 아님 |
| 인앱 신고 버튼 필요 여부 | **불필요** — 생성형 AI 출력이 없으므로 해당 없음 |

> `flutter_tts`는 Android `TextToSpeech` / iOS `AVSpeechSynthesizer`를 호출하는
> **OS 내장 음성 합성**입니다. 프롬프트로 콘텐츠를 생성하는 생성형 AI가 아니므로
> AI 생성 콘텐츠 정책의 적용 대상이 아닙니다.

AI 배지 + 팬더 마스코트가 **동시에** 노출되면, §3.5.5의 "아동 친화적 마케팅 요소"

- 거부 시 대응 비용은 여전히 낮습니다(아이콘 교체 → 즉시 재심사).

  뉴스·잡지 정책을 트리거하지 않습니다.

> ⚠️ **뉴스·잡지 정책과 혼동 주의**
> Google의 「뉴스 및 잡지 앱 선언」 의무는 **앱 이름·아이콘·개발자명·설명에
> '뉴스' 또는 '잡지'가 있거나, 스토어 카테고리가 '뉴스 및 잡지'인 경우**에만
> 발생합니다. 본 앱은 4가지 모두 해당하지 않으므로 **선언 의무가 없습니다.**
> (확인: 스토어 노출 텍스트에 '뉴스'·'잡지' 문자열 0건, 카테고리 = 교육)

> 광고 도입 후에도 등급은 유지될 것으로 예상되나, 설문 재응답 후 IARC가 재산정합니다.

> **"13세 미만 아동**을 주요 대상으로 제작된 앱 → **가족용 자체 인증 광고 SDK만

**→ 광고로 수익을 내실 계획이라면, 타겟층을 반드시 만 13세 이상으로 설정해야
합니다.** 이는 선택이 아니라 필수 조건입니다.

#### 3.8.1.1 「아니요」로 답하는 근거 — 빌드된 APK 실측

선언은 **실제 배포되는 APK의 병합된(merged) AndroidManifest**를 기준으로 해야 합니다.
`app-release.apk`를 `aapt2 dump permissions`로 직접 추출한 결과:

```
package: com.hskwordmaster.flashcards
permission: com.hskwordmaster.flashcards.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
uses-permission: name='com.hskwordmaster.flashcards.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION'
```

**권한이 단 1개뿐이며, 그것도 앱이 스스로 정의한 내부용 권한입니다.**

| 확인 대상 권한 | APK 내 존재 | 의미 |
|---|---|---|
| `INTERNET` | **없음** | **네트워크 통신 자체가 불가능** |
| `ACCESS_NETWORK_STATE` | 없음 | 네트워크 상태 조회 불가 |
| `ACCESS_WIFI_STATE` | 없음 | Wi-Fi 정보 접근 불가 |
| `com.google.android.gms.permission.AD_ID` | 없음 | 광고 ID 미사용 |
| `ACCESS_FINE_LOCATION` / `COARSE` | 없음 | 위치 미수집 |
| `READ_CONTACTS` | 없음 | 연락처 미접근 |
| `CAMERA` | 없음 | 카메라 미사용 |
| `RECORD_AUDIO` | 없음 | 마이크 미사용 |
| `READ_EXTERNAL_STORAGE` | 없음 | 파일 접근 불가 |
| `com.android.vending.BILLING` | 없음 | 인앱 결제 불가 |

> **`INTERNET` 권한이 없다는 것은 결정적입니다.**
> Android에서 네트워크 통신을 하려면 이 권한이 **반드시** 필요합니다.
> 권한이 없으면 앱이 서버로 데이터를 보낼 **물리적 방법이 존재하지 않습니다.**
> 따라서 "수집하거나 공유하지 않는다"는 선언은 검증 가능한 사실입니다.

#### 3.8.1.2 소스 코드 교차 검증

| 검증 항목 | 방법 | 결과 |
|---|---|---|
| 네트워크 호출 | `grep -rniE "http://\|https://\|HttpClient\|Socket\|WebSocket" lib/` | **0건** |
| 서드파티 SDK | `grep -rniE "admob\|firebase\|analytics\|crashlytics\|facebook\|sentry"` | **0건** |
| 계정 생성 | `grep -rniE "signup\|register\|createAccount\|회원가입"` | **0건** |
| 데이터 전송/공유 | `grep -rniE "share\|ACTION_SEND\|Clipboard"` | **0건** |
| 데이터 저장 위치 | `progress_service.dart` | `Hive.initFlutter()` → 기기 내부 앱 전용 저장소 |

**데이터는 기기 내부에만 저장됩니다:**

```dart
// lib/services/progress_service.dart:115-117
await Hive.initFlutter();
_progress = await Hive.openBox<String>(_progressBox);   // word_progress
_meta = await Hive.openBox(_metaBox);                    // app_meta
```

Hive는 기기의 앱 전용 샌드박스 디렉터리에 파일로 저장합니다. 다른 앱이 접근할 수
없고, 개발자도 원격에서 열람할 수 없습니다.

#### 3.8.1.3 「아니요」의 정확한 의미 (오해 방지)

Play Console의 이 질문에서 **"수집(collect)"** 은 다음을 의미합니다.

> **"기기 밖으로 데이터를 전송하는 행위"**

따라서 기기 내부에만 저장하는 것은 **"수집"에 해당하지 않습니다.**
학습 기록을 Hive에 저장하는 것은 데이터 수집이 아닙니다.

| 행위 | 데이터 보안상 "수집" 인가 |
|---|---|
| 기기 내부 Hive에 학습 기록 저장 | **아니요** (기기 밖 전송 없음) |
| 기기 내 TTS 엔진으로 발음 재생 | **아니요** (외부 전송 없음) |
| 이름·이메일 입력받아 서버 전송 | 예 |
| 광고 SDK가 광고 ID를 Google로 전송 | 예 (→ 광고 도입 후) |

**이 구분이 중요한 이유:** "학습 데이터를 저장하니 수집이다"라고 오해해서 「예」로
답하면, 14개 데이터 유형을 하나하나 선언해야 하고 심사 검증도 강화됩니다.
기기 내부 저장은 수집이 아니므로 **「아니요」가 정확합니다.**

#### 3.8.4 중요한 고지

**현재 (v1.0.0)**
- **인터넷 권한을 사용하지 않습니다.** `AndroidManifest.xml`에 `INTERNET` 권한이 없습니다.
- **모든 학습 데이터는 기기 내부(Hive)에만 저장**되며, 개발자는 접근할 수 없습니다.
- **TTS 발음**은 기기 내장 엔진이 처리하며 외부로 전송되지 않습니다.
- **Android 자동 백업**: 기기 백업 기능에 따라 Google 계정 백업 영역에 포함될 수 있으나,
  이는 OS 기능이며 개발자는 접근 불가합니다. 필요 시 `allowBackup="false"`로 차단 가능합니다(6장 참고).

**광고 도입 후 (v1.1.0)**
- 권한 3종 추가: `INTERNET`, `ACCESS_NETWORK_STATE`, `com.google.android.gms.permission.AD_ID`
- **학습 데이터는 여전히 기기 내부에만 저장**되며 광고에 활용되지 않습니다.
- 광고는 **하단 배너만** 사용하며 학습 흐름을 가로막지 않습니다.
- 광고가 없어도(오프라인) 학습 기능은 전부 동작합니다.

## 6. (선택) Android 자동 백업 차단

데이터 보안 선언을 "전송·백업 없음"으로 더 명확히 하려면 `allowBackup`을 끌 수 있습니다.

`android/app/src/main/AndroidManifest.xml`:

```xml
<application
    android:label="HSK 단어마스터"
    android:name="${applicationName}"
    android:icon="@mipmap/ic_launcher"
    android:allowBackup="false"
    android:fullBackupContent="false"
    android:dataExtractionRules="@xml/data_extraction_rules">
```

`android/app/src/main/res/xml/data_extraction_rules.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<data-extraction-rules>
    <cloud-backup>
        <exclude domain="root" />
        <exclude domain="database" />
        <exclude domain="sharedpref" />
        <exclude domain="file" />
    </cloud-backup>
    <device-transfer>
        <exclude domain="root" />
        <exclude domain="database" />
        <exclude domain="sharedpref" />
        <exclude domain="file" />
    </device-transfer>
</data-extraction-rules>
```

> 이 설정을 적용하면 기기 변경 시 학습 기록이 이전되지 않습니다.
> 학습 기록 승계를 원한다면 기본값(백업 허용)을 유지하고, 스토어 설명에
> "학습 기록은 기기 내부에만 저장됩니다"라고 안내하는 현재 방식이 적절합니다.

## 9. 광고 도입 로드맵 (하단 배너)

### 9.1 왜 지금은 넣지 않는가

| 이유 | 설명 |
|---|---|
| 심사 변수 최소화 | 광고는 데이터 보안·등급 설문 재응답을 유발해 심사 지연 위험 |
| 반응 기반 설계 | 실제 사용자가 어느 화면에 머무는지 확인 후 광고 위치 확정 |
| 첫인상 보호 | "4,184개 무료, 광고 없음" 이 초기 다운로드 전환에 유리 |
| 기술 리스크 | AdMob SDK 추가 시 minSdk·권한·ProGuard 이슈 검증 필요 |

### 9.2 배너 배치 원칙

| 화면 | 배너 | 비고 |
|---|---|---|
| 홈 (HomeScreen) | ✅ 하단 고정 | 학습 시작 전 노출, 이탈률 낮음 |
| 단어장 (WordListScreen) | ✅ 하단 고정 | 스크롤 목록 하단은 자연스러움 |
| 통계 (StatsScreen) | ✅ 하단 고정 | 체류 시간 짧아 부담 적음 |
| **학습 (StudyScreen)** | ⚠️ **신중** | 카드 플립 집중도 방해 가능. A/B 테스트 권장 |
| **퀴즈 (QuizScreen)** | ❌ **금지** | 정답 입력 중 오터치 유발, 정책 위반 소지 |

> **절대 금지**: 학습 카드 위에 오버레이되거나, 카드 플립 애니메이션 중
> 리레이아웃을 유발하는 배치. `Scaffold.bottomNavigationBar` 대신
> 본문 Column 하단에 고정 배치하고, SafeArea를 반드시 적용합니다.

### 9.3 수익 예측 (보수적)

|---|---|

| **월 수익** | **3.6만 ~ 9만원** |

> 충당 수준**으로 기대하시고, 수익 확대는 추후 "광고 제거 프리미엄(IAP)"
> 검토를 권장합니다.
